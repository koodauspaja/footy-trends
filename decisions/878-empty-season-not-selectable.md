# 878 — A season with no matches is listed but not selectable: decisions

Bug #878. Spec: `specs/011-current-season-discovery.md`, whose rule is that a page never lands on a season with no matches. `storedTasoSeasons` counts a season with group-standings rows as stored, and the newest stored season decides where a page lands while TASO's newest season is empty. A reader could store such rows by opening the empty season from the selector, and from then on every page of that competition would open on it, empty. Miikka widened the fix to a rule for every competition: a season only announced, with no match listed, is treated as non-existing.

| Decision | Why |
|---|---|
| **A season with no matches stays in the selector, greyed out, as "2027 – Ei otteluita tällä kaudella"** (`SeasonOption.noMatches`, rendered by `SeasonSelect` as a disabled `<option>`) | Miikka's choice over hiding it: a reader sees the next season is coming but cannot open it. This narrows `decisions/865-active-season-has-matches.md`, where the newest season TASO lists stayed a selectable top of the range; it stays the top, not selectable |
| **A season has matches when any of its matches is listed, scheduled or played** | Miikka: a season is selectable before its first match day, for Arvauspeli, but not when no match is listed. As `decisions/865` already counts scheduled matches for the default season |
| **A typed `kausi` naming such a season is invalid**: `parseSeasonParam` and `parseTasoSeasonParam` accept only a choosable option, so the page opens the newest season with matches with the existing notice "Kautta ei löytynyt. Näytetään kausi …" | Miikka left it to Claude. It is what any season the selector does not offer already gets, so there is no new page or wording, and nothing of the empty season is read or stored |
| **Domestic: TASO's newest season is marked when the page lands below it** (`defaultSeason !== currentSeason`) | `resolveTasoSeasonContext` already checks the newest season's matches on every page view, cached 15 minutes, and lands below it only when it has none, so this costs no request |
| **`newestStoredSeason` reads match rows only** | Group rows alone no longer make a season one a page lands on, whoever stored them. `storedTasoSeasons` keeps counting group rows for its other readers, the forced refresh's season list and the zone backfill, which do want every season held. The query keeps their shape, `selectDistinct`, as the existing tests describe |
| **Foreign: football-data's upcoming season is marked unless its fixtures are stored** (`storedForeignSeasons`), on the foreign pages only | Read from the database, never asked of football-data from a page view, so no visitor can spend the shared key (Miikka; the wider exposure is #880). The 03:00 daily refresh (`decisions/080-daily-refresh-of-every-competition.md`) stores an upcoming season's fixtures in production; on staging a new season becomes selectable after `npm run predictions -- refresh`, or when it starts |
| **The national-team pages are left as they are** | Miikka: "it's ok to leave the international side out of this" |
| **The forced refresh is unchanged** | An admin may still refresh an empty season; it builds its own season list |
| **The season-context and season-ceiling cache keys are not bumped** | An entry from before the deploy can hold a newest stored season counted from group rows for at most 15 minutes |
