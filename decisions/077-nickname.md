# 077 — A nickname the user sets up and edits: decisions

Feature #763, `specs/077-nickname.md`. A signed-in user sets, changes or
removes a nickname on `/asetukset`; `Arvauspeli`'s leaderboard (specs/073)
shows players by it. The admin can clear one.

| Decision | Why |
|---|---|
| A table of its own, `user_nickname`, migration `0024_create_user_nickname`: the user as its key, cascading on delete, the nickname as typed, `nickname_key` (unique), and `updated_at` | Spec, API & Data. better-auth rewrites `user` on every sign-in, as `user_avatar`'s record found. Keyed by the user, not the game's player, since the nickname is the user's (S2) |
| The key is the nickname lower-cased in JavaScript, stored beside it, and the unique constraint is on the key, not an index on `lower(nickname)` | Postgres's `lower()` follows the database's locale, and lower-cases only ASCII under `C`, so `Äijä` and `äijä` could both pass. Deciding the key in one place, in the code, does not depend on how an environment's database was made |
| A save first locks the user's `user` row (`for no key update`), then deletes the user's nickname row and inserts the new one, with `on conflict (nickname_key) do nothing`. An insert that writes nothing means another user holds the key, and the transaction is undone | With the user's own row gone, the only conflict left is the key. Postgres makes the second of two users saving the same name at once wait for the first and then find the conflict, so the race needs no error code read off a driver's exception. The lock is for one user's own two saves at once: without it, the second's delete cannot see the first's new row, and its insert would conflict on the user's own key and call their own name taken. `no key update` leaves the foreign-key checks of the user's other rows unblocked. The integration test races two users for one name, and one user against themself |
| Normalised with NFKC, not NFC as the spec first said: a full-width `Ａ` is an `A`, a no-break space a space. Then trimmed and runs of spaces collapsed. The spec now says NFKC | S3's reason for Latin letters only is that a look-alike cannot pass for a taken name. Full-width letters are Latin script, so under NFC `Ａdmin` would sit beside `Admin` |
| Length in code points after normalising, 3 to 20. Anything over 200 characters as sent is refused as too long before any work | S3. A letter outside the basic plane is one character, not two UTF-16 units. The 200 is a parser's bound (`skills/self-review.md`, section 6) |
| Allowed: `\p{Script=Latin}`, `0`–`9`, space, `.`, `_`, `-`. Checked in the order length, characters, word list, and the first broken rule is the one reported | S3. One reason per refusal, the one a user fixes first |
| The word lists live in `src/lib/nickname-word-list.ts`, copied unchanged from LDNOOBW at commit `5faf2ba`, `fi` 130 and `en` 403 entries, with the attribution CC BY 4.0 asks for in its header | S6, S11. A TypeScript module needs no loader in Next, vitest or `tsx`. Copied unchanged, so the attribution's claim stays true and a later copy is a plain replacement |
| A name and each entry are split into words at every character that is not a letter or a digit, lower-cased. An entry matches when its words appear in a row among the name's. An entry with no words, the list's one emoji, is dropped | S6, whole words. Splitting both the same way makes `s&m` and `alfred nussi` match as written. Left in, the emoji would split to nothing and match every name |
| The refusal for a listed word is `Valitse toinen nimimerkki.`, and the log says `word-list`, never the word | S6 |
| `/asetukset` gets a section `Nimimerkki` after `Profiilikuva`, in a component of its own, `nickname-settings.tsx` | S1. `settings-page.tsx` was 505 lines |
| The section's button is `Tallenna nimimerkki`, not `Tallenna` as the spec drafted; the spec now says so | The page's preferences already have a `Tallenna`, and two buttons of one name tell a screen reader nothing about which is which (S10) |
| A refusal is shown under the field with `role="alert"`, linked by `aria-describedby`; the field is marked invalid for a broken rule, not for a failed save | The field's own error, read with it. A failed save is not the field's fault |
| A failed read on `/asetukset` costs the section: `Nimimerkkiä ei voitu ladata.` and no field, logged `Reading the nickname on the settings page failed` | The spec's UX. A field shown empty on a failed read would invite a save over the real one, as the preferences form's record found |
| `/arvauspeli` reads the nickname beside the game, and a failure there is the page's existing `Arvauspelin lataaminen epäonnistui.` | One read of one row by key; a page that half-loads would need a state of its own for a line of text |
| The line `Valitse nimimerkki, jolla näyt tulostaulukossa.` shows under the balance, for a player whose game is in progress, with `nimimerkki` linking to `/asetukset` | S1. The balance is only on the playing view, and the spec places the line under it |
| The admin table gets a column `Nimimerkki` and, on another user's row that has one, `Tyhjennä nimimerkki`, confirmed with `Tyhjennetäänkö käyttäjän {email} nimimerkki?`. A clear says `Nimimerkki tyhjennetty.` | S7. The acting admin's own row keeps having no controls, as decisions/028 has it; their own nickname is removed on `/asetukset` |
| The admin's delete confirmation now reads `Tämä poistaa tilin, suosikit, asetukset, profiilikuvan, nimimerkin ja arvauspelin tiedot.` | It lists what the deletion removes, and the nickname is one more thing; it had also missed the game's data since specs/072 |
| Clearing a nickname already empty, or a user since deleted, answers `ok` | The admin's intent, no nickname, holds either way |
| Log lines, ids only: `Nickname saved` (user, `set` / `changed` / `removed`), `Nickname refused` (user, `length` / `characters` / `taken` / `word-list`), at `info`; no session or a value that is not text at `warn`; a failed save at `error`; `Nickname cleared by admin` (admin, user) at `info`, and `Clearing a nickname failed` at `error` | The spec's Logging |
| The privacy page lists the nickname and that other signed-in users see it in the game's leaderboard, names it among what deleting the account removes, and says `Päivitetty 5.11.2026` | S8. The date moves with what the page says is stored, as specs/071 moved it |
| Tests: unit for the rules at every boundary, the store's answers over a faked client, the action's refusals and log lines, the section, the settings route, the admin table, actions and data, and the game page's line. Integration for the race, a case change of one's own, the key, and the cascade. End to end in `nickname.spec.ts` | Spec, Tests Required |
