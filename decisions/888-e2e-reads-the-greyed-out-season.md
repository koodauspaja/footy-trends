# 888 — e2e reads the greyed-out season, and names no football-data season by year: decisions

Bug #888. The v2.1.0 release run (#887) failed five e2e tests on an empty database with real TASO. Since `decisions/878-empty-season-not-selectable.md`, a season TASO has announced with no match listed is offered first in the season selector, disabled, as "2027 – Ei otteluita tällä kaudella". Specs written before it read every option as a plain, selectable year. Those specs passed locally because the usual run's database already held stored seasons, and #881 merged without a run against an empty one. Miikka asked for the specs that name a fixed football-data season to be fixed in the same change.

| Decision | Why |
|---|---|
| **A spec reads an option's season from its value, and skips a disabled option** | The value is the plain season id whatever the label says, and a disabled option cannot be selected. `cup-domestic` read the label as a number and got `NaN`. `title-metadata` picked the disabled option and waited 30 s for it. `season-simulation` took the second option as the previous season, which a greyed upcoming season would make the current one |
| **`cup-domestic` also checks that only the newest season may be greyed out** | That is the rule `decisions/878` set. Checking it keeps the test about what the selector offers, not only about its years |
| **A football-data season is `lastFinishedSeason()`, from the date, never a year written in the spec** | Measured on 2026-11-24 with the app's key: Bundesliga 2023 answers 200, 2022 answers 403. The key reads the four latest seasons, the ones the selector offers. A fixed year falls out of that window as seasons roll over: Champions League 2023 in August 2027, every 2024 in August 2028. Seasons start in August and end by June, so the previous year from August on, and two years back before it, is a finished season inside the window, with no request to find it |
| **Arsenal stays the club for the Premier League tests** | Each needs a complete Premier League season of one club, and Arsenal has one every year. The figures are read from the page, so none changes with the season |
| **A Champions League club is read from the tables: one in both that season and the one before** (`cupTeamPage`) | No club plays in it every year, so Arsenal would fail in a season it missed. "Tämä kausi verrattuna" compares with the club's previous season, so the club has to have one |
| **The e2e test of the 2023/24 group stage is removed** | The group stage ended with that season, so no season the key reads will have one from August 2027. The rendering is covered by `tests/unit/app/foreign/standings/page.test.tsx` ("renders one table per group for a group-stage season"), and football-data's group field by `tests/unit/lib/football-data/football-data.test.ts` ("maps a group-stage match's group") |
| **A test that opens a team page first opens a standings page that stores its season**: `chart-axis-text`, Liigacup's in `cup-analytics`, and the national team's in `season-summary`. `season-comparison` stores the season before too | A team page finds its club only in stored rows. Each of these read a season only an earlier spec in the full run had stored, so run on an empty database without those specs they showed "Joukkuetta ei löytynyt", or had nothing to compare with. Found by running only the affected specs on an empty database |
| **TASO's and the national teams' fixed seasons stay** | TASO keeps every season, so `kausi=2017` or `2020` is still there. The national teams' tournaments come years apart, so Euros 2024 is the newest one |
| **`team.spec.ts`'s Bundesliga failure is recorded, not fixed beyond the season** | In the release run, the first Bundesliga 2024 request failed: "Sarjataulukon lataaminen epäonnistui", the only request for that season in the run. The job keeps no server output, so whether it was a 429 is not known. Run alone on an empty database it passed in 33 s. Since `decisions/880-bounded-provider-requests.md`, the 60-second cooldown keeps a failed path closed through Playwright's two retries. Before #880, a retry asked again. If it fails again, the next step is to keep the server's output in the release job |
| **The affected specs run against an empty database with real TASO before the pull request, and only they do** | Miikka: the key limit and TASO are not spent on the whole suite, but every spec a change can affect runs on an empty database before the pull request |
